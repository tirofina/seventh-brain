# AI 라우팅 치트시트

> [!summary] 어떤 일을 로컬 Hermes와 Claude 중 누구에게 맡기고, 결과를 볼트에 어떻게 남기는지 정한 규칙이다. 사람, Hermes, Claude 모두 이 규칙을 따른다.

## 1. 라우팅 규칙

판단 기준은 민감도 / 빈도 / 난이도 셋이다.

| 기준 | Hermes (로컬) | Claude (클라우드) |
|---|---|---|
| 민감도 | 개인 기록, 민감 데이터 (PC 밖으로 안 나감) | 공개돼도 되는 내용 |
| 빈도, 양 | 매일, 대량, 백그라운드 (비용 0) | 가끔, 핵심적인 것 |
| 난이도 | 요약, 태그, 분류, 1차 초안 | 설계, 디버깅, 깊은 정리, 최종본 |

애매하면 로컬 Hermes를 먼저 쓰고, 부족하면 Claude로 넘긴다.

## 2. 볼트 규칙

### 2-1. 프런트매터
```yaml
---
tags: []
status: inbox        # inbox | draft | active | evergreen | archived
source: human        # human | hermes | claude  (마지막으로 크게 손댄 주체)
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### 2-2. AI가 쓴 것은 콜아웃으로 표시
콜아웃 제목에는 날짜를 넣지 않는다 (영구 노트에 덧붙일 때만 예외).

| 쓰임 | 형식 | 쓰는 쪽 |
|---|---|---|
| 노트 맨 위 결론 한 줄 | `> [!summary] 한 문장` (펼침) | Hermes, Claude |
| 기술 정보 모음 | `> [!info]- 자세히` (접힘, 노트 맨 아래) | Hermes, Claude |
| Inbox 노트 제안 | `> [!tip]- 자동 제안` (접힘) | Hermes |
| 영구 노트에 덧붙임 | `> [!note] <날짜>에 더한 내용` (펼침) | Claude |
| 데일리 나머지 할 일 | `> [!todo]- 나머지 할 일 N개 (<프로젝트> <개수>, ...)` (접힘) | 밤 정리 |
| 데일리 끝난 일 | `> [!success]- 끝난 일 N개` (접힘) | 밤 정리 |
| 데일리 작업 선호 후보 | `> [!question]- 작업 선호 후보 N개` (접힘) | 밤 정리 |
| 데일리 오늘 한 일 | `> [!done]- 주제: 한 일 한 문장` (접힘, 안에 방법, 결과, 확인할 것, 자세히) | 밤 정리 |
| 노트 사이 어긋남 | `> [!warning]- 어긋남: [[상대 노트]]` (접힘, 노트 끝) | 밤 정리 |
| 데일리 메모 | `> [!note]- HH:MM 한 줄 제목` (접힘) | 대화 중인 Claude, 사람 |

### 2-3. Inbox 흐름
`00_Inbox`에 메모 -> (밤) Hermes가 요약, 태그, 관련 노트 제안 -> (밤) Claude가 정리 -> `02_Notes` 영구 노트. Hermes와 Claude는 사람이 쓴 본문을 고치지 않는다.

### 2-4. 이름과 링크
- 영구 노트는 개념 하나 = 파일 하나, 제목은 명사구.
- 날짜는 데일리, 주간 노트의 이름과 프런트매터에만 쓴다. 작업 기록, 결정 기록, 주제 노트, 영구 노트의 이름에는 날짜를 넣지 않는다.
- 링크는 실제로 있는 노트에만 건다. 없는 노트를 가리키는 링크는 누르면 빈 노트가 생긴다.

### 2-5. 밤 정리 (Claude, 자동)
- 매일 밤 Hermes 단계가 끝나면 밤 정리(Claude Code `claude -p` 또는 Codex)가 화면 없이 깨어나 어제 데일리를 마무리하고 오늘 데일리를 미리 쓰고, 주제 노트와 프로젝트 첫 페이지를 쓰고, `#정리해줘` 노트를 영구 노트로 종합하고, 영구 노트와 결정 기록의 어긋남을 표시하고, 월요일에는 주간 노트를 만든다.
- 지시문: `90_Meta/scripts/gardener-prompt.md`. 밤 정리 자신은 이 파일을 고치지 못한다.
- 데일리 노트는 위에서부터 먼저 할 일, 어제 한 일, 오늘 한 일, 관련 노트, 메모 순이다. 먼저 할 일은 밤 정리가 고른 할 일 최대 3개이고, 그 아래 접힌 콜아웃에 나머지 할 일, 끝난 일, 작업 선호 후보가 있다. 자동 구역(메모 앞까지)은 밤마다 다시 쓰이고, 그 아래 `## 메모`는 보존된다. 자동 구역에서 체크한 할 일은 다음 실행 때 빠지고, 대화에서 정했거나 끝낸 일은 기록을 근거로 끝난 일로 옮겨진다 (체크를 풀면 되살아난다).

### 2-5-1. 작업 선호
- `02_Notes/작업-선호.md`는 Claude와 Codex가 매 세션 따르는 작업 방식이다. 규칙은 한 줄에 하나, 긍정형으로 쓴다.
- 대화 중 작업 방식 지시나 교정은 데일리 메모 `HH:MM 선호: ...`로 남는다. 밤 정리가 이를 데일리의 접힌 작업 선호 후보로 올리고, 사용자가 체크한 것만 "승인된 규칙"에 넣는다.
- Claude Code는 이 노트를 `@경로`로 불러오고, Codex에는 밤마다 `~/.codex/AGENTS.md`로 복사된다 (`sync-prefs.ps1`).

### 2-5-2. 참고 자료 (자동)
- 대화에서 인용하거나 열어 본 논문과 링크는 밤마다 `04_References/<프로젝트>/`에 정리된다 (`collect-references.ps1`). 논문은 한 편에 노트 하나(제목 이름, 저자, 연도, 학술지, 초록, 어디서 썼나), 나머지 링크는 `<프로젝트> 참고 자료.md` 목록.
- 근거를 들 때는 URL이나 DOI를 답에 그대로 적는다. 자동 구역 밖의 `## 메모`는 사람이 쓴다.

### 2-6. 비공개
- `99_Private/`는 밤 정리가 읽지도 고치지도 못한다 (권한 설정으로 막음).
- 그 밖의 폴더는 밤마다 Claude로 보내진다. 민감한 기록은 처음부터 `99_Private/`에 쓴다.

### 2-7. 주제 정리 (Orca 구조를 따른다)
- 대주제는 Orca 프로젝트다. 세션의 작업 폴더로 정확히 정해진다.
- 소주제는 프로젝트 안의 주제어다. 작업 기록은 `01_Projects/<프로젝트>/log/<주제어>/<제목>.md`에 쌓이고, 주제마다 `01_Projects/<프로젝트>/<주제어>.md` 주제 노트가 있다.
- 주제어는 주제 노트의 `description`을 보고 고른다. 주제 범위를 바꾸려면 description을 고친다.
- 볼트의 프로젝트 폴더 이름은 바꿔도 된다. 작업 기록은 첫 페이지(`_index.md`) tags에 Orca 프로젝트 이름이 있는 폴더를 찾으므로 그 tags는 지우지 않는다.
